# 6.8 Unlock

Part of the Lectrix specification. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and [README.md](README.md) lists these files; sections keep the numbers they share, so "section 5.4" is in AGENTS.md and "section 6.5" in [annotations.md](annotations.md).

A PDF's password and restrictions removed, in the file itself or in a copy (ADR 0025). Opening a protected file to read it asks for its password as it always has (section 5.4); Unlock is for a file that should have no protection from now on.

- **Where it is:** **Unlock…** on the start screen, after Organize pages, with an open lock for its icon (section 6.1), and **File > Unlock…**, after Combine files…, at any time (a command without a default shortcut, section 6.6). With a protected document shown, the command unlocks that document, as the button below does; otherwise, and from the start screen, it asks for one PDF in the Open dialog ("Unlock a PDF").
- **A protected document's tab** shows a lock before its name ("Protected: click to see its protection"), whether it has a password, restrictions or both; a click on it opens the document's properties at Security (section 6.10). It goes once the document is unlocked.
- **From a document that refuses a change.** When a document's security settings refuse something (annotating, bookmarks, page labels, changing, inserting or extracting pages, copying text), including a click on an annotation tool they lock, or its shortcut, the notification says so and offers to lift it: "This document's security settings don't allow changing bookmarks. Unlock it to remove its restrictions.", with an **Unlock…** button. Where a panel says what the document's security settings refuse, it has the same button: the Bookmarks panel and the annotation list with nothing to list, the annotation inspector, and the bar of the grid of pages (section 6.7). It unlocks that document's file, with no Open dialog, and with the password the document was opened with, so none is asked. A document with unsaved changes asks first: "Save your changes first? report.pdf has unsaved changes. Unlocking works on the file as it is saved, so save them first." (**Save**, Cancel). A file that refuses to have its pages copied into another (combining, inserting pages from it) says to unlock it first with File > Unlock…, then add the unlocked file.
- **The password.** A file that needs one asks for it in the password dialog, worded for this ("report.pdf is protected. Enter its password to remove it.", the button **Unlock**). Either of its passwords will do, the open password or the permissions password, and the restrictions go with it. A wrong one is asked again ("That password didn't open report.pdf. Check it and try again."); Cancel or Esc ends it. A file with restrictions alone (no printing, copying or changes, but no open password) asks for nothing.
- **Save, or save a copy.** Once the file is open, a dialog asks what to do: "Remove the password? report.pdf is unlocked. Save it without its password and restrictions, or save an unlocked copy and keep the original as it is." **Save** (the main button), **Save as a copy** or **Cancel** (also Esc), which writes nothing. For a signed file it adds: "This file is signed. Its signatures will not be valid in the file saved without the password, because the whole file is rewritten." A signature is valid only in the file that was signed.
- **Save** writes the file itself without encryption, in place (the atomic save of section 7), and opens it in a tab: "report.pdf no longer has a password or restrictions." If it is open in a tab already, that tab reads it again at once, where it was, and everything its restrictions refused is allowed; the change is not reported as one by another program. A tab with unsaved changes (the file unlocked from the start screen or the menu) is left as it is, and warns that its file changed on disk (section 7). Its document then has the protection's removal waiting, so saving its changes over the file keeps the file unlocked.
- **Save as a copy** shows the Save dialog ("Save an unlocked copy"), in the original's folder with "report (unlocked).pdf". The original is only read; the copy opens in a tab: "Saved report (unlocked).pdf without a password or restrictions. The original file is unchanged." A Save dialog given up asks the question again. A copy saved over the original is the same as Save.
- **A file without protection** is said to have none ("report.pdf has no password or restrictions. There is nothing to remove."), and nothing is written.
- **A file that can't be opened** (damaged, not a PDF, protected in a way Lectrix can't open, such as with a certificate) says so in an error notification, as opening it does.

## Settled details

- Any password that opens the file removes everything, the restrictions included, and restrictions alone need no password (the user's decision, 2026-10-19; Acrobat asks for the permissions password whenever a file restricts anything; ADR 0025).
- Save, Save as a copy or Cancel is asked every time, Save first (the user's decision, 2026-10-19).
- The file is written whole, keeping every object: nothing is optimized or recompressed.
- The file is read from disk: unsaved changes to it in a tab are not in what is saved.
